# OpenVidu 세션 동시 생성 방어

## 문제

같은 방에 여러 사용자가 동시에 입장하면 각 요청이 캐시 부재를 확인한 뒤 OpenVidu 세션 생성 API를 중복 호출할 수 있었다. OpenVidu의 `customSessionId`가 최종 리소스 중복은 제한하더라도, 집중 트래픽에서는 불필요한 외부 호출과 409 응답 처리가 늘어난다. 방 삭제가 세션 생성보다 먼저 완료되면 늦게 끝난 생성 결과가 캐시에 다시 남는 경합도 가능했다.

## 구현

- 방 ID를 128개 고정 스트라이프 락에 배정한다.
- 같은 방의 생성과 삭제만 직렬화하고, 서로 다른 방은 병렬 처리한다.
- 락을 획득한 뒤 캐시를 다시 확인하여 동시 요청 중 첫 요청만 외부 생성 API를 호출한다.
- 삭제도 같은 락을 사용하여 생성 중 삭제 요청은 생성 완료 후 세션을 닫고 캐시를 제거한다.
- 고정 개수 락을 사용하여 방 ID가 계속 늘어나도 락 레지스트리가 함께 증가하지 않는다.

## 검증 범위와 한계

- 32개 동시 요청이 외부 생성 API를 한 번만 호출하는지 검증한다.
- 생성과 삭제가 겹쳐도 늦은 생성 결과가 캐시에 남지 않는지 검증한다.
- 이 방어는 단일 애플리케이션 인스턴스 범위다. 여러 서버 인스턴스 사이의 호출 단일화에는 분산 락 또는 OpenVidu 앞단의 멱등 프록시가 추가로 필요하다.
- 사용자별 OpenVidu 연결 토큰은 접속마다 별도 리소스이므로 장기 캐시하지 않는다.
