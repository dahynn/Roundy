# 코드 리뷰 변경분 PR 복사 문서 — 2026-09-07

현재 8개 수정 브랜치는 로컬에만 있습니다. GitHub push·PR 생성은 아직 하지 않았습니다. master에 이미 병합된 변경으로 오인하지 마세요.

## 병합 순서

1번부터 순서대로 진행합니다. 아래 base는 기능별 diff만 보이도록 하는 **검토용 부모 브랜치**입니다. 앞 PR이 병합되면 다음 PR의 base를 master로 바꾸고 Files changed를 확인한 뒤 병합합니다.

이 누적 브랜치는 `Create a merge commit`으로 부모 커밋을 보존하는 방식이 가장 단순합니다. `Squash and merge` 또는 `Rebase and merge`를 사용했다면 다음 PR 전에 브랜치 기준을 다시 정리해야 합니다. 한꺼번에 master로 PR을 열면 앞 PR의 변경까지 중복 표시될 수 있습니다.

검증 근거와 남은 위험은 [리뷰 보고서](./code-review-2026-09-07.md)에 있습니다. 실제 카메라 6인 E2E·공개 배포 완료 문구는 넣지 않았습니다.
